# 기사 범위로 주제를 고르는 기술사·감리사 심화 로드맵

> [!info] 현재 우선순위
> **주제는 정보처리기사 필기 범위와 기술사·감리사의 공통분모에서 먼저 고르고, 학습 깊이는 감리사·정보관리기술사에 맞춘다.** 기사 필기 형식의 집중 연습은 실제 응시 시기가 정해지면 시험 전 몇 주 동안 한다. 최종 목표는 정보관리기술사 합격이다.

**이어가기:** [[정보처리기사/07-학습-진도|학습 진도]]에서 다음 지점을 확인한다. 기존 [[정보처리기사/00-학습-허브|학습 허브]]는 개념 노트의 목차로 쓴다.

## 주제 선정과 학습 깊이

- **주제 선택:** 향후 응시를 고려해 [Q-Net의 2027~2029년 정보처리기사 출제기준](https://www.q-net.or.kr/crf005.do?id=crf00503s02&jmCd=1320)을 기준으로 삼는다(확인: 2026-10-30). 그 범위에서 [[01-공식-기출-교집합-분석|기술사·감리사 공식 기출]]에도 나타나는 개념을 우선한다. 아래 묶음은 학습용 분류이며, 세부 출제 항목과의 대응은 원문 첨부를 대조해 확정한다. 기관의 공식 중복률은 아니다.
- **학습 깊이:** 기사 출제기준은 주제 선택의 기준이지 설명의 상한이 아니다. 선택한 주제의 선수 개념부터 원리, 대안·한계, 설계·운영 사례, 감리 확인 자료와 개선안, 기술사식 서술까지 다룬다.
- **순서:** 세 시험의 공통 주제를 먼저 진행한다. 기사에만 필요한 세부 암기·문법형 문제는 기사 집중 구간에, 기술사·감리사에만 필요한 별도 주제는 공통 주제를 거친 뒤 배치한다. 한 번 다뤘다는 사실을 숙달로 간주하지 않는다.

| 기사 필기 과목별 주제 선택 축 | 함께 심화할 공통 주제의 예 |
|---|---|
| 소프트웨어 개발 | 요구사항·UML·아키텍처, 테스트·품질, 변경·형상관리 |
| 데이터베이스 구축 | 모델링·정규화, SQL·인덱스, 트랜잭션·복구 |
| 프로그래밍 언어 활용 | 자료구조·알고리즘, 언어의 실행 원리와 코드 해석 |
| 정보시스템 구축 관리 | 운영체제·네트워크, 성능·가용성·재해복구, 보안·사업관리 |

## 필기에서 겹치는 학습축

두 시험의 필기는 공통 기술 개념을 많이 활용한다. 아래는 **Q-Net의 정보관리기술사 시험과목·출제경향**과 **NIA의 감리사 필기 5과목**을 연결한 학습용 분류다. 기관이 두 시험의 세부 출제범위가 동일하다거나 공식 중복률을 발표한 것은 아니다.

공식 공개 기출 60회차·12개년을 확보해 확인한 주제별 교집합과 집계 한계는 [[01-공식-기출-교집합-분석|공식 기출 교집합 분석]]에 정리했다.

| 공통 학습축 | 함께 익힐 개념의 예 |
|---|---|
| 소프트웨어공학 | 요구사항, 설계·아키텍처, 개발 과정, 품질과 테스트 |
| 데이터베이스 | 데이터 모델, 정규화, 인덱스, 트랜잭션, 데이터 관리 |
| 시스템 구조 | 운영체제, 네트워크, 시스템 구성, 성능과 가용성 |
| 보안 | 접근 통제, 암호화, 취약점, 운영 통제 |
| 사업관리·감리 접점 | 프로젝트 위험, 품질·변경 관리, 점검과 개선 판단 |

예를 들어 **인덱스**의 원리와 조회·갱신 성능의 균형은 함께 공부한다. 기술사 답안에서는 선택 이유와 대안·한계를 서술하고, 감리사 필기에서는 주어진 설계와 근거를 보고 적절한 조치를 판별하는 식으로 연습한다.

## 두 시험을 함께 준비하는 이유와 구분

| 공통 개념을 배울 때 | 기술사 답안으로 바꾸기 | 감리사 판단으로 바꾸기 |
|---|---|---|
| 원리·구성·선택 기준·제약을 설명한다 | 정의 → 원리·구성 → 대안 비교·적용 조건 → 실무 적용과 한계를 짧게 쓴다 | 감리 기준·위험·통제의 적절성을 문제 조건에서 판별하고, 어떤 자료로 확인할지 설명한다 |

- 같은 주제라도 시험 형식은 다르다. [Q-Net 정보관리기술사 시험정보](https://www.q-net.or.kr/crf005.do?gId=&gSite=Q&id=crf00503s02&jmCd=0601&jmInfoDivCcd=B0)는 필기를 단답형·논술형(100분씩 4교시)으로 안내한다.
- [NIA 정보시스템감리사 자격검정 안내](https://auditor.nia.or.kr/front/cmmn/pageLink.do?link=/front/guide/guide01&menuId=g02_0101)의 필기 과목은 **감리 및 사업관리, 소프트웨어공학, 데이터베이스, 시스템구조, 보안**이다. [2026년 시행공고](https://auditor.nia.or.kr/front/guide/bbsView.do?nttSn=2064&bbsSn=4)의 필기는 객관식이다. 필기 이후 면접과 이론·실무교육이 이어지며, 실무 결과보고서 작성은 실무교육 단계다.
- 위 공식 안내는 **2026-10-30 확인**. 시험 일정·자격·세부 기준은 실제 응시를 결정할 때 최신 공고로 다시 확인한다.

## 학습일 한 번의 진행 방식

하루 1~2시간을 쓸 수 있으면 다음 순서로 진행한다. 시간은 권장치이며 공부할 수 있는 날에만 진행한다.

1. **5~10분 복습:** 이전 개념을 노트 없이 한두 문장으로 회상한다. 맞혔던 문제라도 찍은 경우 다시 확인한다.
2. **20~25분 개념:** 정의, 작동 원리, 간단한 그림/흐름, 관련 개념과의 차이를 설명한다. 필요한 선수 개념이 약하면 여기서 보완한다.
3. **20~25분 사례:** 실제 제약이 있는 상황에서 선택·설계·실패 경로와 대안을 비교한다. 사용자가 먼저 판단하고 근거를 말한다.
4. **15~20분 감리 관점:** 어떤 위험이 있는지, 무엇을 증거로 확인할지, 미흡하면 어떤 조치를 제안할지 연습한다. 감리사 객관식을 쓰더라도 오답 선택지의 문제점을 함께 설명한다.
5. **15~25분 기술사식 답안:** 처음에는 5~8줄로 핵심을 구조화하고, 익숙해지면 분량과 시간 제한을 늘린다. 개념 정확성·누락·판단 근거를 피드백한다.

30분 이하라면 **복습 5분 → 핵심 개념 10분 → 사례·감리 질문 10분 → 2~3문장 답안 5분**으로 한 주제만 한다. 매 학습 후 확인된 혼동과 다음 지점을 기록하며, 완료한 학습 3~4회마다 통합 사례로 연결한다. ‘한 번 접함’은 숙달로 표시하지 않고 **설명 가능 → 사례 적용 가능 → 근거를 들어 판단 가능**을 따로 확인한다.

## 학습 블록

1. **소프트웨어 개발 공통 주제:** 주문·결제의 정상/실패 흐름을 시작점으로 요구사항 추적성, 상태 전이, 시퀀스, 예외 처리, 테스트와 확인 증거를 연결한다. 이어 아키텍처·품질·형상관리를 다룬다.
2. **데이터베이스 구축 공통 주제:** 모델링·정규화·SQL·인덱스·트랜잭션·동시성·복구를 성능·정합성·운영 위험과 함께 다룬다.
3. **프로그래밍 언어 활용 공통 주제:** 자료구조·알고리즘·코드 실행 원리를 설계와 성능 판단까지 연결한다. C·Java의 세부 문법은 필요한 만큼 Python과 비교한다.
4. **정보시스템 구축 관리 공통 주제:** 운영체제·네트워크·성능·가용성·보안·백업·재해복구를 사례로 통합한다.
5. **공통 주제 이후의 별도 보강:** 감리 절차·사업관리의 고유 기준, 기술사 최신 기술과 서술 구성·시간 관리를 따로 보강한다. 공통 주제 안에서도 감리사·기술사 수준의 판단과 서술은 처음부터 연습한다.

블록은 달력상 주차가 아니다. 진도와 이해도에 따라 순서를 조정하고, 새 주제를 시작하기 전 [[정보처리기사/07-학습-진도|학습 진도]]를 확인한다. C·Java 문법은 공통 시스템 이해나 시험 문제에 필요할 때 보완하고 Python 경험과 비교해 설명한다.

## 정보처리기사 집중 구간

실제 응시일이 정해지면 **시험 전 약 3~4주**를 임시 집중 구간으로 잡는다. 시작할 때 필기 과목별 진단 문제로 빈틈을 확인하고, 남은 시간과 결과에 따라 기간을 조정한다. 그 구간에는 과목별 약점 보완, 기출 유형, 시간 제한 객관식에 집중한다. 기술사·감리사 학습에서 얻은 원리를 기사 문제에 연결한다.

## 바로 다음 학습

기존 주문·결제 실패 경로 4지선다 문제는 **아직 답을 받지 않아 미완료**다. 이는 기사 필기의 소프트웨어 개발 범위와 기술사·감리사의 공통 주제인 요구사항·설계 검토의 첫 사례다. 먼저 요구사항과 시퀀스 다이어그램에서 정상 경로와 실패 경로를 왜 모두 확인해야 하는지 설명한 뒤, 결제 실패·응답 지연·중복 요청이 주문 상태에 주는 영향을 판단한다. 이어 감리 관점의 확인 자료와 5~8줄 기술사식 설명을 연습한다.
