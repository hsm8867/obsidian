# 기술사·감리사 중심 학습 로드맵

> [!info] 현재 우선순위
> **정보관리기술사와 정보시스템감리사에 필요한 이해·적용·판단을 먼저 훈련한다.** 정보처리기사 필기는 실제 시험 시기가 정해지면 시험 전 몇 주 동안 진단과 기출 중심으로 집중한다. 최종 목표는 정보관리기술사 합격이다.

**이어가기:** [[정보처리기사/07-학습-진도|학습 진도]]에서 다음 지점을 확인한다. 기존 [[정보처리기사/00-학습-허브|학습 허브]]는 개념 노트의 목차로 쓴다.

## 두 시험을 함께 준비하는 이유와 구분

| 공통 개념을 배울 때 | 기술사 답안으로 바꾸기 | 감리사 판단으로 바꾸기 |
|---|---|---|
| 원리·구성·선택 기준·제약을 설명한다 | 정의 → 원리·구성 → 대안 비교·적용 조건 → 실무 적용과 한계를 짧게 쓴다 | 요구사항·위험 → 확인할 설계/시험/운영 증거 → 발견사항의 근거 → 개선 또는 확인 질문을 제시한다 |

- 같은 주제라도 시험 형식은 다르다. [Q-Net 정보관리기술사 종목 안내](https://www.q-net.or.kr/crf005.do?id=crf00503&jmCd=0601)는 필기를 단답형·논술형(100분씩 4교시)으로 안내한다.
- [NIA 정보시스템감리사 자격검정 안내](https://auditor.nia.or.kr/front/cmmn/pageLink.do?link=/front/guide/guide01&menuId=g02_0101)의 필기 과목은 **감리 및 사업관리, 소프트웨어공학, 데이터베이스, 시스템구조, 보안**이다. 필기 이후 면접과 이론·실무교육도 이어진다.
- 위 공식 안내는 **2026-10-30 확인**. 시험 일정·자격·세부 기준은 실제 응시를 결정할 때 최신 공고로 다시 확인한다.

## 학습일 한 번의 진행 방식

하루 1~2시간을 쓸 수 있으면 다음 순서로 진행한다. 시간은 권장치이며 공부할 수 있는 날에만 진행한다.

1. **5~10분 복습:** 이전 개념을 노트 없이 한두 문장으로 회상한다. 맞혔던 문제라도 찍은 경우 다시 확인한다.
2. **20~25분 개념:** 정의, 작동 원리, 간단한 그림/흐름, 관련 개념과의 차이를 설명한다. 필요한 선수 개념이 약하면 여기서 보완한다.
3. **20~25분 사례:** 실제 제약이 있는 상황에서 선택·설계·실패 경로와 대안을 비교한다. 사용자가 먼저 판단하고 근거를 말한다.
4. **15~20분 감리 관점:** 어떤 위험이 있는지, 무엇을 증거로 확인할지, 미흡하면 어떤 조치를 제안할지 연습한다. 감리사 객관식을 쓰더라도 오답 선택지의 문제점을 함께 설명한다.
5. **15~25분 기술사식 답안:** 처음에는 5~8줄로 핵심을 구조화하고, 익숙해지면 분량과 시간 제한을 늘린다. 개념 정확성·누락·판단 근거를 피드백한다.

30분 이하라면 **복습 5분 → 핵심 개념 10분 → 사례·감리 질문 10분 → 2~3문장 답안 5분**으로 한 주제만 한다. 매 학습 후 확인된 혼동과 다음 지점을 기록하며, 완료한 학습 3~4회마다 통합 사례로 연결한다. ‘한 번 접함’은 숙달로 표시하지 않고 **설명 가능 → 사례 적용 가능 → 근거를 들어 판단 가능**을 따로 확인한다.

## 학습 블록

1. **요구사항과 설계 검토:** 주문·결제의 정상/실패 흐름을 시작점으로 요구사항 추적성, 상태 전이, 시퀀스, 예외 처리, 테스트와 확인 증거를 연결한다.
2. **소프트웨어공학과 사업관리:** 개발 생명주기, 아키텍처, 품질·테스트, 변경·형상·사업 관리와 감리 판단을 연결한다.
3. **데이터베이스:** 모델링·정규화·인덱스·트랜잭션·동시성·복구를 성능·정합성·운영 위험과 함께 다룬다.
4. **시스템·보안·운영:** 구조, 가용성, 성능, 네트워크, 접근 통제, 로그, 백업·재해복구를 사례로 통합한다.
5. **감리와 기술사 전용 훈련:** 감리 절차·사업관리·증거 기반 발견사항과 기술사 서술 구성·시간 관리·시사 주제를 별도로 보강한다.

블록은 달력상 주차가 아니다. 진도와 이해도에 따라 순서를 조정하고, 새 주제를 시작하기 전 [[정보처리기사/07-학습-진도|학습 진도]]를 확인한다. C·Java 문법은 공통 시스템 이해나 시험 문제에 필요할 때 보완하고 Python 경험과 비교해 설명한다.

## 정보처리기사 집중 구간

실제 응시일이 정해지면 **시험 전 약 3~4주**를 임시 집중 구간으로 잡는다. 시작할 때 필기 과목별 진단 문제로 빈틈을 확인하고, 남은 시간과 결과에 따라 기간을 조정한다. 그 구간에는 과목별 약점 보완, 기출 유형, 시간 제한 객관식에 집중한다. 기술사·감리사 학습에서 얻은 원리를 기사 문제에 연결한다.

## 바로 다음 학습

기존 주문·결제 실패 경로 4지선다 문제는 **아직 답을 받지 않아 미완료**다. 새 우선순위에 맞춰 이 사례를 첫 심화 블록으로 삼는다. 먼저 요구사항과 시퀀스 다이어그램에서 정상 경로와 실패 경로를 왜 모두 확인해야 하는지 설명한 뒤, 결제 실패·응답 지연·중복 요청이 주문 상태에 주는 영향을 판단한다. 이어 감리 관점의 확인 자료와 5~8줄 기술사식 설명을 연습한다.
