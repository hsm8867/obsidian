## 데이터베이스·정규화

- [ ] `COUNT(*)`와 `COUNT(점수)`는 무엇이 다른가? → 전자는 조건에 맞는 **모든 행**, 후자는 `점수`가 `NULL`이 아닌 행을 센다. [[01-데이터베이스#집계와 그룹 조건]]
- [ ] `WHERE 점수 >= 80`에 80·90이 맞으면 `COUNT(*)` 결과는? → 값 목록이 아닌 **2**. [[01-데이터베이스]]
- [ ] A의 주문금액이 10·20, B가 30이면 `HAVING SUM(금액) >= 30` 결과는? → **A와 B 모두**. [[01-데이터베이스]]
- [ ] 기본키에 중복값·`NULL`을 넣을 수 있는가? → **둘 다 안 된다.** [[01-데이터베이스#기본키와 외래키]]
- [ ] 수량은 상품 테이블인가, 주문항목 테이블인가? → **주문항목**. 같은 상품도 주문마다 수량이 다르다. [[02-정규화#2NF와 부분 종속]]
- [ ] 1NF·2NF·3NF 차이는? → **한 칸 한 값 / 복합키 일부 종속 제거 / 이행 종속 제거**. [[02-정규화#빠른 판별]]
- [ ] `COMMIT` 후 장애가 나도 결과가 남는 성질은? → **지속성**, 일관성과 구분. [[01-데이터베이스#트랜잭션과 ACID]]

## 프로그래밍 언어

- [ ] `a[]={2,4,6}; p=a; *p=*p+1; p=p+1;` 뒤 `a[0]`과 `*p`는? → **3·4**. 원소 대입은 a[0]을 3으로 바꾸고, 포인터 대입은 p를 a[1]로 옮긴다. 분리 확인에서 `*p=7`의 결과 `7 8`은 맞혔지만, p를 옮긴 뒤 `*p=*p+1`을 `6 8`로 선택했다. 위치만 묻는 후속 문제에서는 `p=p+1`을 정수 5→6으로 해석하고 `*p`를 주소라고 여겨 오류를 예상했다. 재설명 뒤 p가 a[1]을 가리키고 `*p`가 9인 문제를 맞혔다. 이어 `p=p+1; *p=9`의 출력 `5 9`를 맞히고 a[1]이 바뀐다고 설명했다. 간격을 두고 복습한다. [[03-프로그래밍-언어#C 배열과 포인터 연산]]
- [ ] `swap(int a,int b)`에서 a·b를 교환하면 호출한 쪽 x·y도 교환되는가? → **복사본 a·b만 교환된다.** x=2·y=7이면 함수 안은 a=7·b=2가 되어도 main의 x·y는 2·7이다. 후속 확인에서는 함수 안의 n을 8로 출력한 뒤 main의 x를 3으로 출력하는 `8 3`을 맞혔다. 각 printf가 읽는 변수를 확인하고 간격을 두고 복습한다. [[03-프로그래밍-언어#포인터 인수로 값 교환하기]]
- [ ] C에서 `int x=3; int y=x; y=8;` 실행 뒤 x는? → **3**. y에는 x의 값이 복사되고, 이후 y에 대입하면 y만 바뀐다. 후속 확인 `a=4; b=a; b=b+2;`의 결과 `4 6`은 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#값 복사와 포인터 대상 변경]]
- [ ] `int x=2; int y=5; int *p=&x; p=&y; *p=9;` 실행 뒤 x·y는? → **2·9**. 마지막 대입 시점에 p가 가리키는 변수는 y다. 재설명 후 대상만 묻는 미세 확인은 b로 맞혔다. 이후 a=3·b=8에서 p를 b에서 a로 바꾸고 역참조로 2를 더하는 결과 `5 8`도 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#값 복사와 포인터 대상 변경]]
- [ ] Java 메서드 안에서 `a = new int[]{9,9};`로 바꾸면 호출한 쪽 x도 새 배열을 가리키는가? → **아니다.** 복사된 참조값을 가진 지역 매개변수 a만 바뀌고 x는 기존 배열을 가리킨다. 후속 확인에서 원소를 7로 바꾼 뒤 a에 새 배열을 대입해도 x는 `{7,2}`로 남아 합계가 9라고 맞혔고, 그 이유도 직접 설명했다. 선언·원소 대입·참조값 재대입의 용어를 구분하고 간격을 두고 복습한다. [[03-프로그래밍-언어#배열 인수와 참조값의 복사]]
- [ ] `int i=5; do{i++;}while(i<3);` 실행 뒤 i는? → **6**. 본문에서 5를 6으로 증가시킨 뒤 `6<3`을 검사한다. 같은 조건의 while은 본문을 실행하지 않아 5다. [[03-프로그래밍-언어#do-while과 중첩 반복문]]
- [ ] `int n=1; do{n+=2;}while(n<5);`에서 n은 7까지 증가하는가? → **5에서 종료한다.** 1→3 뒤 조건은 참, 3→5 뒤 `5<5`는 거짓이다. 거짓이면 다음 본문으로 돌아가지 않는다. 후속 확인에서 do-while 종료 값 4를 맞혔고, 초기값 6·조건 `n<4`·본문 `n=n-2`의 while 결과 6과 do-while 결과 4도 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#do-while과 중첩 반복문]]
- [ ] Java에서 길이가 3인 배열을 `i=0; i<=a.length; i++`로 순회하면 정상 종료하는가? → **아니다.** `a[0]`부터 `a[2]`까지 출력한 뒤 `a[3]`에서 실행 중 범위 초과 예외가 발생한다. 전체 순회는 `i < a.length`, 마지막 원소는 `a[a.length - 1]`로 접근한다. 2026-10-28 추가 확인에서는 마지막 원소 접근과 예외 이후 문장의 실행 여부 2문제를 모두 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#배열 경계와 실행 중 오류]]
- [ ] 길이 2 배열의 `a[2]`를 C와 Java에서 읽으면 둘 다 범위 초과 예외가 보장되는가? → **아니다.** Java는 실행 중 `ArrayIndexOutOfBoundsException`이 발생하지만, C는 정의되지 않은 동작이다. C에서 끝 다음 포인터 `a+2`를 만들 수 있다는 앞선 문제는 맞혔지만, 두 언어의 범위 밖 읽기 비교에서는 둘 다 반드시 예외가 난다는 보기를 선택했다. 해설 후 C에서 우연히 숫자가 출력돼도 정의되지 않은 동작이라는 후속 확인을 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#C 배열 경계와 끝 다음 위치]]
- [ ] `char s[]="cat";`에서 `sizeof(s)`와 `strlen(s)`는? → **4와 3**. 배열에는 널 문자 `'\0'`까지 4개의 `char`가 저장되어 4바이트이고, `strlen`은 널 문자 앞의 3개를 센다. 처음에는 `3 3`을 선택하고 `sizeof`가 기억나지 않는다고 밝혔다. 해설 후 `"hi"`의 결과 `3 2`와 크기를 직접 정한 `char s[6]="hi";`의 결과 `6 2`를 맞혔다. 배열의 저장 공간과 문자열 길이를 간격을 두고 복습한다. [[03-프로그래밍-언어#C 문자열의 널 종료와 길이]]
- [ ] `char a[]="cat"; char b[]="cat";`에서 `strcmp(a,b)==1`인가? → **아니다. `strcmp(a,b)==0`이다.** 내용이 같으면 정확히 0을 반환한다. 처음에는 `==1` 보기를 선택했지만, 별개 배열의 `a==b`가 거짓이라는 점은 직접 짚었다. `==`는 시작 주소, `strcmp`는 내용 비교다. 후속 `strcmp("cat","car")>0`은 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#C 문자열 내용 비교]]
- [ ] `Animal a = new Dog();`에서 `a.name`은 Dog의 필드인가? → **아니다. Animal 타입 변수 `a`를 통해 접근하므로 Animal의 필드다.** 첫 문제에서 `a.name + " " + a.sound()`를 `dog dog`로 선택했지만 실제는 `animal dog`다. 이어 `Dog d = new Dog(); Animal a = d;`의 `a.name + " " + d.name`도 `dog dog`로 선택했지만 실제는 `animal dog`다. 한 값만 묻는 `a.name` 확인은 `animal`로 맞혔다. 수치 혼합 전이에서는 `Parent x = new Child();`의 `x.count + " " + x.value()`를 `10 100`으로 답했지만 실제는 **`10 200`**이다. 이어 메서드 한 값 `x.value()`는 200으로 맞혔고, 선택 기준이 반환값인지 질문했다. 필드는 선언 타입, 재정의된 인스턴스 메서드는 실제 객체 기준으로 판단하며 반환값 유무는 관계없다. `void` 메서드를 포함한 혼합 문제에서 `PC`를 맞혔다. 간격을 두고 혼합 적용을 복습한다. [[03-프로그래밍-언어#Java 필드 숨김과 메서드 오버라이딩]]
- [ ] `sum(int a, int b)`와 `sum(int x, int y)`를 한 클래스에 함께 선언할 수 있는가? → **없다.** 매개변수 이름을 지우면 둘 다 `sum(int, int)`로 같은 시그니처다. 오버로딩 선언 판별에서 이름만 바꾼 ①을 선택했지만, 정답은 매개변수 개수를 바꾼 ③ `sum(int)`이었다. 반환 타입이나 접근 제어자만 바꿔도 같은 시그니처의 중복 선언이다. 이후 `show(int)`에 타입을 바꾼 `show(String)`을 더할 수 있다는 확인은 ②로 맞혔다. 간격을 두고 복습한다. [[03-프로그래밍-언어#Java 메서드 오버로딩]]
- [ ] 생성자 매개변수와 필드가 모두 `value`일 때 `value = value;`는 컴파일 오류인가? → **아니다.** 같은 이름은 허용되며 매개변수가 필드를 가린다. 양쪽 `value`가 모두 매개변수라 자기대입이고, `int value = 1`로 초기화한 필드는 1을 유지한다. 이 문제에서 컴파일 오류인 ④를 선택했지만 정답은 ③ `1`이었다. 필드를 바꾸려면 `this.value = value;`라고 쓴다. 후속 확인 뒤 간격을 두고 복습한다. [[03-프로그래밍-언어#Java 생성자와 객체 초기화]]
- [ ] Java에서 `double r = 7 / 2;`를 출력하면? → **3.0**. 오른쪽 정수 나눗셈으로 3을 먼저 구한 뒤 double에 저장한다. [[03-프로그래밍-언어#계산 후 대입]]
- [ ] Java에서 `int n = 3.5;`는 자동으로 3을 저장하는가? → **컴파일 오류**. double 값을 int에 자동으로 대입할 수 없다. [[03-프로그래밍-언어#계산 후 대입]]
- [ ] `int a=3; int b=a++;`에서 `a, b`는? → **4, 3**. 후위 증가는 기존 값을 먼저 사용한다. [[03-프로그래밍-언어#C의 전위·후위 증감]]
- [ ] `new String("hi")`를 두 번 호출한 `a, b`에 `a == b`는? → **false**. 두 객체의 내용이 같아도 참조가 다르다. `a.equals(b)`는 true. [[03-프로그래밍-언어#Java 참조 비교]]
- [ ] `String b = a`라면 `a == b`는? → **true**. 새 객체를 만들지 않는다. [[03-프로그래밍-언어]]

## 운영체제·네트워크

- [ ] 한 프로세스에 스레드가 하나뿐인가? → **아니다.** 여러 스레드가 메모리 일부를 공유할 수 있다. [[05-운영체제와-네트워크#프로세스와 스레드]]
- [ ] CPython GIL이 스레드 생성 자체를 하나로 제한하는가? → **아니다.** 일반 빌드에서 Python 코드 실행의 동시성을 제한한다. [[05-운영체제와-네트워크#Python의 GIL과 헷갈리지 않기]]
- [ ] 라운드 로빈에서 시간이 끝나도 작업이 남으면? → **대기 줄 뒤로 이동**한다. 너무 짧은 시간 할당량은 문맥 교환 비용을 키운다. [[05-운영체제와-네트워크#라운드 로빈 CPU 스케줄링]]
- [ ] 고정 크기의 페이지·프레임을 쓰는 방식은? → **페이징**. 가변 크기 세그먼트는 세그먼테이션이다. [[05-운영체제와-네트워크#가상 메모리와 페이징]]
- [ ] 페이지 크기가 4 KiB라면 바이트 단위 페이지 내부 변위는? → `4096 = 2^12`이므로 **12비트**. [[05-운영체제와-네트워크#가상 메모리와 페이징]]
- [ ] 페이지 크기가 4 KiB이고 페이지 2가 프레임 5에 있다면, 가상 주소 9000의 물리 주소는? → `9000 = 2 × 4096 + 808`, 따라서 `5 × 4096 + 808 = 21288`. **변위는 그대로**다. [[05-운영체제와-네트워크#주소 변환: 페이지 번호만 바뀐다]]
- [ ] 유효한 주소의 페이지가 물리 메모리에 없다면? → **페이지 부재**. 필요한 페이지를 적재해 실행을 이어간다. 잘못된 주소 접근과 구별한다. [[05-운영체제와-네트워크#페이지 부재와 스래싱]]
- [ ] 빈 프레임이 있으면 요청한 페이지가 없어도 적중인가? → **아니다. 요청 직전 RAM에 요청한 페이지가 없으면 부재**다. 적재 후 RAM에 생겨도 이번 접근은 부재로 센다. [[05-운영체제와-네트워크#적중과 페이지 부재]]
- [ ] TLB 미스는 곧 페이지 부재인가? → **아니다.** 변환 결과가 TLB에 없어도 페이지는 RAM에 있을 수 있다. [[05-운영체제와-네트워크#페이지 부재와 스래싱]]
- [ ] 스래싱은 TLB 적중 때문에 생기는가? → **아니다.** 페이지 교체·입출력이 지나치게 잦아지는 상태다. [[05-운영체제와-네트워크#페이지 부재와 스래싱]]
- [ ] 페이지를 `1 → 2 → 3 → 1` 순서로 참조한 뒤 4를 넣을 때, LRU 교체 대상은? → **페이지 2**. 마지막 사용 시점이 2번째로 가장 오래됐다. FIFO는 적재 순서를 유지하므로 페이지 1을 교체한다. [[05-운영체제와-네트워크#페이지 교체: FIFO와 LRU]]
