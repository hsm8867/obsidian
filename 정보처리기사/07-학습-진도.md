## 다시 확인할 개념

사용자가 직접 어려움을 밝히거나 실제 오답으로 확인된 부분을 기록한다. [[06-오답-복습]]의 모든 항목이 실제 오답이라는 뜻은 아니다.

- **정규화:** 1NF·2NF·3NF가 직관적으로 와닿지 않아 전체 설명과 시각화를 요청했다.
- **인덱스:** 조회·삽입/삭제의 성능 차이는 알고 있었지만 주관식 정의를 어떻게 쓸지 어려워했다.
- **라운드 로빈:** 개념을 모르고 찍어서 맞혔다고 밝혔다.
- **스레드와 GIL:** Python이 프로세스당 스레드 하나만 쓰는지 혼동했다.
- **계산 후 대입:** 처음에는 Java `double r = 7 / 2;`를 3.5로 답했다. 해설 후 `double r = 11 / 4;`를 2.0으로 맞히고, 정수끼리 나눠 정수 결과가 된다고 직접 설명했다.
- **Java 자료형 검사:** 처음에는 `int n = 3.5;`가 3을 저장한다고 답했다. 해설 후 `int n = 2.9;`를 컴파일 오류로 맞혔다. 다음에는 명시적 형 변환이 있을 때와 비교한다.
- **Java 배열 경계:** 값 읽기와 합계는 맞혔지만, 길이 3인 배열을 `i <= a.length`로 순회할 때 5·10·15 출력 후 정상 종료한다는 보기를 선택했다. 해설 후 마지막 인덱스 `a.length - 1`과 예외 이후 출력 여부의 추가 확인 2문제를 모두 맞혔다. 간격을 두고 복습한다.
- **C와 Java의 배열 범위 밖 읽기:** C에서 `a+2`를 만들 수 있지만 읽으면 정의되지 않은 동작이라는 확인 문제는 맞혔다. 그러나 길이 2 배열의 `a[2]`를 읽는 C·Java 비교에서는 둘 다 반드시 범위 초과 예외가 난다는 ④를 선택했다. Java는 실행 중 예외를 발생시키지만 C는 숫자 출력·종료 등 어느 결과도 보장하지 않는다고 설명했다. 우연히 숫자가 출력돼도 정의되지 않은 동작이라는 후속 확인을 맞혔다. 간격을 두고 복습한다.
- **C 문자열 크기와 길이:** `char s[]="cat";`에서 `sizeof(s)`·`strlen(s)`의 결과를 `3 3`으로 답하고 `sizeof`가 기억나지 않는다고 밝혔다. 배열에는 널 문자까지 네 칸이 있어 크기는 4바이트, 문자열 길이는 3이다. 저장 공간과 널 문자 앞까지의 길이를 분리해 설명한 뒤 `"hi"`의 결과 `3 2`와 크기를 직접 정한 `char s[6]="hi";`의 결과 `6 2`를 맞혔다. 간격을 두고 복습한다.
- **C 문자열 내용 비교:** 별개 배열 a·b의 내용이 모두 `"cat"`일 때 참인 식으로 `strcmp(a,b)==1`인 ④를 선택했다. 실제 정답은 `strcmp(a,b)==0`인 ②다. `a==b`가 거짓인 이유는 별개 배열이라는 점으로 직접 설명했다. 후속 `strcmp("cat","car")>0`은 맞혔다. `strcmp`의 0과 양수·음수를 간격을 두고 복습한다.
- **Java 필드 숨김·재정의 메서드:** `Animal a = new Dog();`에서 `a.name + " " + a.sound()`가 `dog dog`라는 ④를 선택했다. 실제는 `animal dog`인 ②다. 같은 객체를 `Dog d = new Dog(); Animal a = d;`로 두 타입에서 참조해 `a.name + " " + d.name`을 읽는 후속 문제에서도 `dog dog`인 ①을 선택했지만 실제는 `animal dog`인 ③이다. `a.name` 한 값 확인은 `"animal"`로 맞혔다. 새 이름·숫자의 `Parent x = new Child(); x.count + " " + x.value()`는 `10 100`으로 답했지만 실제는 `10 200`이다. 필드 10은 맞혔고, 메서드는 실제 Child 구현 200임을 다시 설명했다. `x.value()` 한 값은 200으로 맞혔다. 선택 기준이 반환값인지 질문해, 반환값 유무와 무관하게 재정의된 인스턴스 메서드는 실제 객체 기준임을 설명했다. `void show()` 혼합 문제는 `PC`로 맞혔다. 간격을 두고 복습한다.
- **Java 오버로딩:** 같은 이름에 매개변수 개수·타입이 다른 메서드 정의를 소개했다. `show(3)`과 `show("3")`의 출력 `intString`인 ②를 맞혔다. 선언 판별에서는 `sum(int a, int b)`에 이름만 다른 `sum(int x, int y)`를 추가할 수 있다는 ①을 선택했지만, 두 선언은 모두 `sum(int, int)`로 중복된다. 정답은 매개변수 개수를 바꾼 `sum(int)`인 ③이다. 반환 타입·접근 제어자도 시그니처를 구별하지 못한다고 설명했다. 타입 변경 미세 확인에서 `show(String)`인 ②를 맞혔다. 오버라이딩 결합 문제에서 `print(3); print("3");`의 출력 `CS`인 ②도 맞혔다. 간격을 두고 복습한다.
- **Java `this`와 이름 가림:** 필드 `value=1`, 생성자 매개변수 `value=7`인 코드에서 `value = value`를 컴파일 오류 ④로 답했다. 실제는 매개변수 자기대입이라 필드 1을 출력하는 ③이다. 같은 이름의 매개변수가 필드를 가리지만 선언 자체는 허용된다고 설명했다. `this.value = value`로 바꾼 후속 문제에서는 출력 7인 ③을 맞혔다. 간격을 두고 복습한다.
- **Java 정적 메서드와 인스턴스 필드:** `static int read() { return value; }`에서 객체별 `value=5`가 출력되는 ②를 선택했다. 실제는 정적 메서드에 특정 객체가 없어 `value` 직접 참조가 컴파일 오류인 ③이다. `Box b = new Box(); return b.value;`의 결과는 ① `5`로 맞혔다. `static int read()`의 `int`는 반환형이라고 설명했지만, 메서드 안에 `int value=7; return value;`를 둔 문제에서는 필드값 5인 ①을 선택했다. 실제는 지역 변수 7인 ②다. `value + this.value`의 12는 ③으로 맞혔다. 간격을 두고 복습한다.
- **Java `switch`의 연속 실행:** `n=2`에서 `case 2`의 `B` 뒤에 `break`가 없고 `case 3`이 `C`를 출력하는 문제를 ① `B`로 답했다. 실제는 ② `BC`이며, 일치하는 `case`에서 시작하면 `break`를 만날 때까지 다음 `case`의 문장도 실행한다. 후속 확인이 필요하다.
- **C 값 복사:** `int x=3; int y=x; y=8;` 뒤 x를 8로 답했다. 해설 후 `a=4; b=a; b=b+2;`의 결과 `4 6`은 맞혔다. 간격을 두고 복습한다.
- **C 함수의 복사본 교환:** `swap(int a,int b)`를 x=2·y=7로 호출한 뒤 main에서 x·y를 출력하면 `7 2`라고 답했다. 실제 출력은 `2 7`이며 함수 안의 a·b만 교환된다. 해설 후 함수의 n=8과 main의 x=3을 각각 출력하는 결과 `8 3`은 맞혔다. 간격을 두고 복습한다.
- **C 포인터 대상 변경:** `p=&x` 후 `p=&y; *p=9;`에서 x·y를 `9 5`로 답했다. 추가 확인에서도 a=4·b=6·p=&b 뒤 `*p=*p+1`의 결과를 `5 6`으로 답했다. 실제 결과는 각각 `2 9`, `4 7`이다. 재설명 후 현재 대상 미세 확인은 b로 맞혔고, a=3·b=8에서 p를 b에서 a로 바꾼 뒤 `*p=*p+2`의 결과 `5 8`도 맞혔다. 간격을 두고 복습한다.
- **C 배열 원소 대입과 포인터 이동:** `a[]={2,4,6}; p=a; *p=*p+1; p=p+1;` 뒤 `a[0]`과 `*p`를 `2 5`로 답했다. 실제 결과는 `3 4`다. 분리 확인에서 `*p=7`은 맞혔지만, `p=p+1; *p=*p+1`의 결과를 `6 8`로 답했다. 실제는 `5 9`다. 이어서 p를 첫 원소의 값 5로, `*p`를 주소로 해석해 현재 대상 문제에서 오류를 예상했다. p는 첫 원소의 주소를 받고, `p=p+1` 후 두 번째 원소를 가리키며, `*p`는 그 정수 값을 읽는다고 재설명했다. 위치 확인과 `p=p+1; *p=9` 뒤의 출력 `5 9`를 모두 맞혔고, 이동 전후 원소를 각각 바꾸는 출력 `6 8`도 맞혔다.
- **배열 매개변수 재대입:** `a=new int[]{9,9}`를 실행한 뒤 호출한 쪽 `{1,2}` 배열의 `x[0]`을 9로 답했다. 해설 후 원소 변경과 재대입을 결합한 확인 문제는 맞혔고, x가 `{7,2}`로 남는 이유도 직접 설명했다. 원소 대입·새 배열 생성·참조값 재대입을 선언과 구분해 표현하고 간격을 두고 복습한다.
- **while·do-while 검사 시점과 종료:** 처음에는 `int i=5; do{i++;}while(i<3);`의 결과를 5로 답했다. 추가 확인에서도 초기값 4·조건 `n<2`의 while 결과를 5로, `n=1`에서 2씩 증가하는 `do...while(n<5)` 결과를 7로 답했다. 실제 값은 각각 6, 4, 5다. 재설명 후 do-while 종료 값 4와, 초기값 6·조건 `n<4`에서 while 결과 6·do-while 결과 4를 모두 맞혔다. 간격을 두고 복습한다. 중첩 반복과 안쪽 break의 실행 횟수는 모두 맞혔다.
- **페이징:** 고정 크기 페이지·프레임 대신 가변 크기 세그먼트 보기를 선택했다.
- **페이지 내부 변위:** 4 KiB에서 비트 수를 구하는 문제를 몰라 찍었다. `4096 = 2^12`를 확인해야 한다.
- **페이지 부재:** 유효한 주소인데 메모리에 없는 상황을 잘못된 주소 접근과 혼동했다.
- **적중과 부재:** FIFO·LRU 해설 후에도 두 개념이 헷갈린다고 밝혔다. 요청 직전 RAM 상태를 기준으로 설명한 뒤 기본 사례 2개를 모두 맞혔고, 교체가 포함된 `2 → 5 → 2 → 7 → 5`의 FIFO·LRU 횟수도 맞혔다. 이후 간격을 두고 복습한다.
- **스래싱:** TLB 적중률 보기로 찍었다. 잦은 페이지 교체와 입출력이라는 정의를 다시 확인해야 한다.
- **LRU:** 참조 `1 → 2 → 3 → 1` 뒤 교체 대상으로 페이지 3을 선택했다. 페이지 1의 최근 사용 기록을 갱신하면 오래된 순서는 `2 → 3 → 1`이며, 교체 대상은 페이지 2다. 뒤이어 `4 → 1`을 참조할 때 FIFO·LRU 모두 부재 5회라는 보기를 선택했다. LRU는 1이 남아 마지막 참조가 적중하므로 부재 4회라는 점을 표로 설명했다.

추가 확인 문제에서는 **8 KiB의 변위 13비트**, **유효한 페이지의 페이지 부재**, **스래싱의 정의**를 모두 맞혔다. 주소 변환 적용 문제도 정답을 선택했으며, 요청에 따라 페이지 번호·변위를 구하고 프레임 번호로 바꾸는 계산을 다시 설명했다. 한 번의 정답으로 숙달을 단정하지 않는다.

FIFO·LRU 추가 적용에서는 프레임 2개·참조 순서 `2 → 5 → 2 → 7 → 5`의 **LRU 교체 대상 5**, **FIFO 부재 3회·LRU 부재 4회**를 모두 맞혔다.

OPT 적용에서는 현재 페이지 1·2·3, 새 페이지 4, 이후 참조 `2 → 1 → 3`일 때 **페이지 3을 교체**한다고 맞혔다. 요청에 따라 OPT의 비교 기준 역할도 설명했다.

벨라디 현상 명칭, LRU·OPT의 부재 횟수 성질, OPT의 미래 참조 기준 복습 **3문제도 모두 맞혔다**. 가상 메모리·페이징·주소 변환·적중/부재·스래싱·FIFO/LRU/OPT·벨라디 현상을 이번 기초 학습 범위로 마무리했다. 운영체제에는 다른 스케줄링·동기화·파일 관리 등 남은 범위가 있다.

## 다음 학습

**Java `switch` 후속 확인 문제의 답변을 기다린다.** 아래는 하나의 Java 소스 파일 `Main.java`이며, 출력 결과를 묻는다. `System.out.print`는 줄바꿈하지 않는다.

```java
public class Main {
    public static void main(String[] args) {
        int n = 1;
        switch (n) {
            case 1: System.out.print("A");
            case 2: System.out.print("B"); break;
            default: System.out.print("C");
        }
        System.out.print("D");
    }
}
```

① `AD` · ② `ABD` · ③ `ABCD` · ④ `BD`

미응답 문제를 완료한 학습으로 집계하지 않는다. 답변 후 [[03-프로그래밍-언어#Java switch와 break]]의 연속 실행과 `break` 이후 `switch` 바깥 문장의 실행을 해설한다.
