# 데이터베이스: SQL·키·인덱스·트랜잭션

[[00-학습-허브]] · [[02-정규화]] · [[06-오답-복습]]

## 집계와 그룹 조건

| 점수 |
|---:|
| 70 |
| 80 |
| 90 |
| `NULL` |

```sql
SELECT COUNT(*) FROM 성적;    -- 4: 모든 행을 센다.
SELECT COUNT(점수) FROM 성적; -- 3: 점수가 NULL인 행은 세지 않는다.
SELECT COUNT(*) FROM 성적 WHERE 점수 >= 80; -- 2: 80, 90인 행
```

`COUNT(*)`의 결과는 **해당하는 값 목록이 아니라 행의 개수**다. `WHERE`는 행을 먼저 거르고, `GROUP BY`는 행을 묶으며, `HAVING`은 묶인 결과에 조건을 적용한다.

```sql
-- 주문: (A, 10), (A, 20), (B, 30)
SELECT 고객
FROM 주문
GROUP BY 고객
HAVING SUM(금액) >= 30;
-- 결과: A와 B. A의 합계도 30, B의 합계도 30이다.
```

`HAVING COUNT(*) = 2`는 **행이 두 개인 그룹**을 고른다. `(A,10), (A,20), (B,40), (C,5), (C,7)`이라면 A와 C가 해당한다.

## 조인

테이블 A의 `id`가 `1, 2`, B의 `id`가 `2, 3`이라고 하자.

| 조인 | 결과의 A.id | 이유 |
|---|---|---|
| `INNER JOIN` | 2 | 양쪽에 모두 있는 `id`만 남는다. |
| `A LEFT JOIN B` | 1, 2 | 왼쪽 A의 모든 행이 남고, 짝이 없는 1의 B쪽 열은 `NULL`이 된다. |

## 기본키와 외래키

- **기본키(Primary Key)**: 각 행을 식별한다. **중복 값과 `NULL`이 허용되지 않는다.** 이미 `회원ID=102`가 있으면 다른 행에 102를 넣을 수 없고, 기본키를 `NULL`로 둘 수도 없다.
- **외래키(Foreign Key)**: 다른 테이블의 키를 참조해 테이블 사이의 관계와 참조 무결성을 유지한다. 예를 들어 `주문.고객번호`가 `고객.고객번호`를 참조한다.

## 인덱스

**인덱스**는 특정 열의 값을 이용해 행을 빠르게 찾도록 만든 별도 자료구조다. 각 행 앞에 번호를 단순히 매기는 것과 다르다.

```text
조건에 맞는 행이 적음 → 인덱스로 위치를 찾고 필요한 행만 읽기 유리
거의 모든 행이 필요함 → 테이블 전체를 읽는 편이 유리할 수 있음
삽입·수정·삭제        → 인덱스도 갱신해야 하므로 비용 증가
```

인덱스는 저장 공간도 사용한다. 따라서 조회 조건과 데이터 분포를 고려해 만든다. [[02-정규화]]는 중복을 줄이는 설계 단계이고, 인덱스는 조회 경로를 빠르게 만드는 수단이다.

## 트랜잭션과 ACID

트랜잭션은 함께 처리해야 하는 작업의 단위다. `COMMIT`은 변경을 확정하고, `ROLLBACK`은 아직 확정하지 않은 변경을 취소한다.

| 속성 | 뜻 | 기억할 말 |
|---|---|---|
| **원자성** Atomicity | 작업 전체가 실행되거나 모두 취소된다. | 전부 또는 전무 |
| **일관성** Consistency | 트랜잭션 전후에 정해진 데이터 제약을 지킨다. | 규칙 유지 |
| **격리성** Isolation | 동시 실행 중인 트랜잭션끼리 간섭하지 않도록 한다. | 동시 실행 제어 |
| **지속성** Durability | `COMMIT`된 결과가 장애 후에도 보존된다. | 확정 후 보존 |

> [!example] 구분
> `COMMIT` 직후 시스템이 꺼져도 변경 결과가 남아 있어야 하는 성질은 **지속성**이다. 서로 다른 트랜잭션이 동시에 작업할 때 간섭을 제어하는 성질은 **격리성**이다.
