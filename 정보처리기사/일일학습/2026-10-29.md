## 오늘 다룬 내용

- **Java 오버로딩 선언 판별 문제는 오답**이었다. 기존 `sum(int a, int b)`에 추가할 유효한 오버로드로 매개변수 이름만 다른 ① `sum(int x, int y)`를 선택했다. 실제 정답은 매개변수 개수가 다른 ③ `sum(int a)`다.
- 매개변수 이름을 지우고 타입만 남기면 앞의 두 선언은 모두 `sum(int, int)`로 같은 시그니처다. 반환 타입이나 접근 제어자만 바꿔도 구별되지 않는다. [[03-프로그래밍-언어#Java 메서드 오버로딩]]
- **매개변수 타입을 바꾼 후속 확인은 정답**이었다. 기존 `show(int)`에 추가할 오버로드로 `show(String)`인 ②를 선택했다. 매개변수 이름만 다른 선언, 반환 타입만 다른 선언, 접근 제어자만 다른 선언은 모두 `show(int)`와 중복된다고 해설했다.
- **오버로딩·오버라이딩 결합 문제도 정답**이었다. `Parent x = new Child(); x.print(3); x.print("3");`의 출력 `CS`인 ②를 선택했다. `int` 호출은 Child가 재정의한 본문 C, `String` 호출은 상속받은 Parent 본문 S라는 순서로 해설했다. [[03-프로그래밍-언어#Java 메서드 오버로딩]]
- **Java 생성자 첫 출력 문제는 정답**이었다. `new Box(7)`이 `Box(int v)` 생성자를 호출하고 `value = v`로 필드를 7로 초기화하므로 ② `7`을 선택했다. [[03-프로그래밍-언어#Java 생성자와 객체 초기화]]
- **`this`와 이름 가림 첫 문제는 오답**이었다. `int value = 1; Box(int value) { value = value; }`에서 컴파일 오류인 ④를 선택하고 이름이 같아서 그런지 질문했다. 같은 이름은 허용되며, 양쪽 `value`가 생성자 매개변수를 가리키므로 필드는 초기값 1을 유지한다. 실제 정답은 ③ `1`이다. `this.value`가 필드, 이름만 쓴 `value`가 매개변수임을 다시 설명했다. 후속 `this.value = value` 문제에서는 필드에 7이 저장되는 결과인 ③ `7`을 맞혔다. [[03-프로그래밍-언어#Java 생성자와 객체 초기화]] · [[06-오답-복습]]
- **생성자 오버로딩과 객체별 필드값 문제는 정답**이었다. `new Box()`는 필드를 2로 설정하는 생성자, `new Box(5)`는 전달된 값을 필드에 저장하는 생성자를 호출하므로 ② `2 5`를 선택했다. 생성자는 매개변수 구성이 다르면 함께 정의할 수 있고, 두 객체의 필드는 독립적이라고 해설했다. [[03-프로그래밍-언어#Java 생성자와 객체 초기화]]
- **`static` 필드와 인스턴스 필드 적용 문제는 정답**이었다. `new Box(2)`, `new Box(5)`에서 객체별 `value`는 2·5이고, 생성자에서 두 번 증가한 공유 `Box.count`는 2이므로 ③ `2 5 2`를 선택했다. [[03-프로그래밍-언어#Java static 필드와 인스턴스 필드]]
- **공유 필드와 객체별 필드 변화 추적 문제도 정답**이었다. `a.add()` 두 번과 `b.add()` 한 번 뒤 공유 `Box.count`는 3, 객체별 `a.value`와 `b.value`는 2·1이므로 ④ `3 2 1`을 선택했다. [[03-프로그래밍-언어#Java static 필드와 인스턴스 필드]]
- **정적 메서드의 인스턴스 필드 직접 접근 문제는 오답**이었다. `static int read() { return value; }`에서 객체별 `value=5`가 출력되는 ②를 선택했지만, 정적 메서드에는 특정 객체를 가리키는 `this`가 없어 컴파일 오류인 ③이 정답이다. `b.value`처럼 객체를 명시하면 접근할 수 있다고 설명했다. [[03-프로그래밍-언어#Java static 메서드]] · [[06-오답-복습]]
- **명시적 객체를 사용한 후속 문제는 정답**이었다. `static read()` 안에서 `Box b = new Box(); return b.value;`를 실행하면 5를 출력하므로 ①을 선택했다. 이어 `static int read()`가 `value`를 별도로 선언하는지 질문해, `int`는 반환형이고 지역 변수는 따로 선언해야 한다고 설명했다. `b`는 지역 참조 변수, `b.value`는 그 객체의 필드다. [[03-프로그래밍-언어#Java static 메서드]]
- **지역 변수와 필드의 이름 가림 확인은 오답**이었다. 필드 `value=5`가 있고 정적 메서드 안에 `int value=7; return value;`를 썼을 때 ① `5`를 선택했다. 실제 정답은 ② `7`이다. 메서드 안에서 실제로 선언된 지역 변수가 같은 이름의 필드보다 우선해 읽힌다고 설명했다. [[03-프로그래밍-언어#Java static 메서드]] · [[06-오답-복습]]
- **지역 변수와 객체 필드를 함께 읽는 후속 문제는 정답**이었다. 인스턴스 메서드의 `value + this.value`에서 지역 변수 7과 필드 5를 더한 ③ `12`를 선택했다. [[03-프로그래밍-언어#Java static 메서드]]
- **배열 범위 초과와 `try`·`catch`·`finally` 흐름 문제는 정답**이었다. 길이 2 배열의 `a[2]`에서 예외가 발생해 숫자와 `A`는 출력되지 않고, `catch`의 `B`와 `finally`의 `C`가 이어지는 ④ `BC`를 선택했다. [[03-프로그래밍-언어#Java 예외 처리 기본 흐름]]

## 복습 질문

- `sum(int a, int b)`와 `sum(int x, int y)`는 서로 다른 메서드 시그니처인가?
- Java에서 메서드 이름이 같을 때 무엇이 달라야 오버로딩할 수 있는가?
- 오버로딩과 오버라이딩이 한 코드에 있으면 어느 메서드를 호출하는지 어떤 순서로 판단하는가?
- `new Box(7)`은 어떤 생성자를 호출하며, 생성자 안의 필드 대입은 언제 반영되는가?
- 생성자 매개변수와 필드 이름이 모두 `value`일 때 `value`와 `this.value`는 각각 무엇을 가리키는가?
- `new Box()`와 `new Box(5)`는 어떤 생성자를 각각 호출하는가? 두 객체의 인스턴스 필드는 공유되는가?
- 서로 다른 두 객체에서 `static` 필드를 증가시키면 결과가 합쳐지는가? 각 객체의 일반 필드도 함께 변하는가?
- `a.add()`를 두 번, `b.add()`를 한 번 실행하면 공유 필드와 각 객체의 필드는 몇 번씩 바뀌는가?
- 정적 메서드에서 객체별 필드를 이름만으로 읽으면 왜 컴파일 오류인가?
- `static int read()`의 `int`, `Box b = new Box()`의 `b`, `b.value`는 각각 무엇을 뜻하는가?
- 메서드 안에 `int value=7;`이 선언되어 있으면 `return value;`는 필드와 지역 변수 중 무엇을 읽는가?
- 인스턴스 메서드에서 `value`와 `this.value`가 함께 나오면 각각 어느 값을 읽는가?
- `try` 안의 배열 접근에서 예외가 나면 그 뒤의 출력문과 `catch`·`finally`는 어떤 순서로 실행되는가?
