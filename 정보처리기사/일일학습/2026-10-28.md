## 오늘 다룬 내용

- 전날 제시한 Java 배열 기초 3문제 중 **1·2번 정답으로 2/3**이었다. `a[2]`가 30이라는 값 읽기와 2·4·6의 누적 합계 12는 맞혔다.
- 길이 3인 배열을 `i <= a.length`로 순회하는 3번에서 정상 종료 보기를 선택했다. 실제로는 5·10·15를 출력한 뒤 `a[3]`에서 실행 중 범위 초과 예외가 발생한다는 점을 표로 해설했다.
- 배열 길이와 마지막 유효 인덱스, `i < a.length`와 `i <= a.length`, 컴파일 오류와 실행 중 예외를 구분했다. 오류 이전 출력은 남고, 예외 처리가 없는 코드에서는 오류 이후 문장을 실행하지 않는다는 점을 설명했다.
- 배열 경계 추가 확인 **2문제 모두 정답**이었다. 마지막 원소는 `a[a.length - 1]`로 접근하며, `{3,6}`을 `i <= a.length`로 순회하면 3·6 출력 후 오류가 발생해 뒤의 99는 출력하지 않는다고 맞혔다.
- 배열 원소 변경 적용 **3문제 모두 정답**이었다. `a[1]=a[0]+5`의 결과 7, 원소별 2배 갱신 후 마지막 값 6, 앞 원소를 누적한 배열 `{1,3,6,10}`의 마지막 값 10을 맞혔다. 변경된 값이 다음 계산에 반영되는 과정을 표로 설명했다.
- **while·break·continue 적용 3문제 모두 정답**이었다. while의 1부터 3까지 합계는 6, i가 3일 때 break하면 1·2 출력 후 반복문 밖의 9 출력, continue이면 3만 제외한 합계 12라는 결과를 맞혔다.
- **do-while·중첩 반복문 적용은 2·3번 정답으로 2/3**이었다. 바깥 2회·안쪽 3회의 실행 횟수 6과, 안쪽 break가 있을 때 바깥 3회마다 2번씩 증가해 합계 6이라는 결과는 맞혔다.
- `int i=5; do{i++;}while(i<3);`의 결과를 5로 답했다. 본문에서 6으로 증가한 뒤 조건을 검사하므로 출력은 6이라는 과정을 표로 해설하고, 같은 조건의 while은 0회 실행되어 5라는 점과 비교했다.
- while·do-while 추가 확인 **2문제는 모두 오답(0/2)**이었다. 초기값 4·조건 `n<2`의 비교에서 A(while)=5·B(do-while)=5를 선택했으나 실제로는 A=4·B=5다. `n=1`에서 2씩 증가하고 `n<5`를 검사하는 do-while에서는 7을 선택했으나 실제 결과는 5다.
- while은 첫 조건이 거짓이면 본문을 실행하지 않는다는 점과, do-while도 매번 본문 뒤 조건을 검사해 거짓이면 즉시 반복을 종료한다는 점을 다시 설명했다. 1→3에서 참, 3→5에서 거짓이 되는 실행을 표와 단계별 시각화로 추적했다. 선택 결과만 기록하며 혼동 원인은 단정하지 않는다.
- 종료 조건에 집중한 추가 확인 **1문제는 정답**이었다. `n=2`에서 본문으로 2를 더한 뒤 `n<4`를 검사하는 코드의 출력 4를 선택했다. `2→4`, `4<4`는 거짓이므로 종료한다는 과정을 해설했다.
- 초기 조건이 거짓인 while과 do-while의 비교 확인 **1문제도 정답**이었다. 초기값 6·조건 `n<4`·본문 `n=n-2`에서 A(while)는 6, B(do-while)는 4를 선택했다. 후속 두 확인에서 정답을 선택했으므로 다음 개념으로 진행하고, 검사 시점은 간격을 두고 복습한다.
- **Java 메서드 코드 문제 3개 모두 정답**이었다. twice(4)의 반환값 8, plus(x)에서 int 매개변수만 바꿔 x=5·y=8이 되는 합계 13, f(3)=5·f(6)=5의 합계 10을 맞혔다. 조건 안에서 return을 만나면 현재 호출이 끝나는 점을 확인했다.
- **배열 인수 전달 적용 문제는 1·3번 정답으로 2/3**이었다. 같은 배열의 첫 원소를 9로 바꾸는 경우와, int 변수 x=3을 유지하면서 배열 원소를 10으로 바꿔 합계 13이 되는 경우는 맞혔다.
- 메서드에서 `a = new int[]{9,9};`를 실행한 뒤 호출한 쪽 `x[0]`을 읽는 2번에 9를 선택했다. 실제로는 x가 기존 `{1,2}`를 계속 가리켜 결과는 1이다. a에 새 참조값을 대입하는 것은 x의 참조값을 바꾸지 않는다는 점을 연결 그림으로 해설했다.
- 배열 원소 변경·참조값 재대입 추가 확인 **1문제는 정답**이었다. 사용자가 기존 배열의 첫 원소를 7로 바꾼 뒤 a에 새 배열을 대입해도 x는 `{7,2}`로 남는다고 직접 설명했다. 마지막 합계는 9이며, 이후 `a[1]=8`은 새 배열만 바꾼다는 점을 표로 해설했다.
- 표현을 다듬어 `a[0]=7`은 원소 대입, `a=new int[]{9,9}`는 새 배열 생성 후 참조값 재대입으로 구분했다. **C 주소·포인터 첫 확인은 1번만 정답으로 1/3**이었다. `p=&x` 뒤 `*p=7`로 x를 바꾸는 경우는 맞혔다.
- `int x=3; int y=x; y=8;` 뒤 x를 8로 답했으나 실제 값은 3이다. `p=&x` 후 `p=&y; *p=9;`를 실행할 때는 x·y를 `9 5`로 답했으나 실제 결과는 `2 9`다. 값 복사 후 별개 변수에 대입하는 경우와 포인터의 현재 대상 변경을 표로 추적해 설명했다.
- C 값 복사·포인터 대상 변경 추가 확인은 **1번만 정답으로 1/2**이었다. `a=4; b=a; b=b+2;`의 결과 `4 6`은 맞혔다. `a=4`, `b=6`에서 p를 b로 바꾼 뒤 `*p=*p+1`을 실행하는 문제는 `5 6`으로 답했으나 실제 결과는 `4 7`이다.
- `p=&b` 뒤 양쪽 `*p`가 모두 b에 접근하므로 해당 문장을 `b=b+1`로 읽는 과정을 다시 설명했다. 현재 대상만 묻는 미세 확인 **1문제는 정답**이었다. `p=&a` 다음 `p=&b`를 실행한 뒤 대상은 b라고 선택했다. 선택 결과만으로 혼동 원인은 단정하지 않는다.
- 주소 재대입 후 역참조 실행 결과 확인 **1문제도 정답**이었다. a=3·b=8에서 p를 b에서 a로 바꾸고 `*p=*p+2`를 실행하는 결과 `5 8`을 선택했다. 그 시점의 대입은 `a=a+2`로 읽는다고 해설했다. 선택 정답을 근거로 다음 개념에 진행하고, 포인터 대상 추적은 간격을 두고 복습한다.
- **C 함수의 값·포인터 인수와 반환값 확인 3문제 모두 정답**이었다. 값 인수의 복사본만 수정하면 x=3 유지, 포인터로 수정하면 x=5, 반환값을 x에 다시 대입해도 x=5라는 결과를 맞혔다.
- **C 포인터 인수 응용은 2·3번 정답으로 2/3**이었다. 포인터로 호출자 변수의 값을 교환하는 결과 `7 2`와, `p=q` 뒤 y만 9로 바뀌는 결과 `2 9`는 맞혔다.
- 일반 int 매개변수 a·b를 교환한 뒤 호출자 x·y를 출력하는 1번에서 `7 2`를 선택했다. 실제 출력은 `2 7`이다. 함수 안의 복사본 a·b는 교환되지만 main의 x·y는 그대로라는 점을 표로 설명했다.
- 함수 안·밖 출력 구분 추가 확인 **1문제는 정답**이었다. 함수 안에서 n을 8로 바꿔 출력한 뒤, main에서 그대로인 x=3을 출력하는 결과 `8 3`을 선택했다. 복사본과 호출한 쪽 변수는 간격을 두고 복습한다.
- **C 배열과 포인터 적용 3문제 모두 정답**이었다. `*(p+1)`로 두 번째 원소 20을 읽고, p를 두 번째 원소로 옮겨 9를 대입한 뒤 배열이 `{2,9,6}`이 되는 결과, `*p`와 `*(p+2)`로 첫째·셋째 원소 `3 9`를 읽는 결과를 맞혔다.
- 이어서 `*p+1`은 현재 원소의 값에 1을 더하고, `*(p+1)`은 다음 원소의 값을 읽는다는 차이를 설명했다. 계산만 하는 표현식은 p나 배열을 바꾸지 않는다. 구분 적용은 **1·2번 정답, 3번 오답으로 2/3**이었다. `*p+1`과 `*(p+1)`의 결과 `4 5`, `p=a+1` 뒤의 `20 30`은 맞혔다.
- `a[]={2,4,6}; p=a; *p=*p+1; p=p+1;` 뒤 `a[0]`과 `*p`에 `2 5`를 선택했다. 실제 결과는 `3 4`다. 원소 값 대입 후 포인터 위치 이동을 표로 분리해 설명했다.
- 두 동작을 나눠 묻는 추가 확인은 **1번 정답, 2번 오답으로 1/2**였다. `*p=7`이 첫 원소를 바꾼 결과 `7 8`은 맞혔다. `p=p+1; *p=*p+1`의 결과로 `6 8`을 선택했으나 실제는 두 번째 원소가 8→9로 바뀌어 `5 9`다. p를 옮긴 직후의 대상과 그다음 원소 대입을 다시 설명했다.
- 현재 대상 확인 문제에서 `int *p=a`를 첫 원소 값 5로 해석하고, `p=p+1`이 6을 저장하며, `*p`가 주소를 출력하므로 오류가 난다고 추론해 ④를 질문했다. 실제로 p에는 첫 원소 주소가 저장되고, 이동 후에는 두 번째 원소를 가리켜 `*p`는 정수 8이다. `printf("%d",*p)`가 8을 출력하는 이유와 주소 출력 형식 `%p`를 구분해 설명했다.
- **p와 `*p`의 의미 재확인 1문제는 정답**이었다. `a[]={4,9}`에서 p를 한 원소 옮기면 a[1]을 가리키고 `*p`가 9라는 ③을 선택했다.
- **이동 뒤 원소 대입 확인도 정답**이었다. `a[]={5,8}; p=a; p=p+1; *p=9;`의 출력 `5 9`를 선택했고, p가 a[1]의 주소를 저장한 뒤 `*p=9`가 a[1]을 바꾼다고 직접 설명했다.
- **이동 전후 원소 수정 혼합 문제도 정답**이었다. `a[]={4,7}`에서 첫 원소를 2 더해 6으로 바꾼 뒤 p를 옮기고, 두 번째 원소를 1 더해 8로 바꾼 출력 `6 8`을 선택했다. [[03-프로그래밍-언어#원소 값 연산과 주소 연산 구분]]
- **C 배열 경계 확인 1문제도 정답**이었다. `a[]={5,8}; p=a+2`에서 포인터 초기화는 가능하지만 `*p`로 읽으면 정의되지 않은 동작이라는 ③을 선택했다. `a[2]`도 같은 범위 밖 접근이며, Java 길이 2 배열의 `a[2]`는 실행 중 범위 초과 예외를 일으킨다는 차이를 설명했다. [[03-프로그래밍-언어#C 배열 경계와 끝 다음 위치]]
- **C와 Java의 범위 밖 읽기 비교 1문제는 오답**이었다. 두 언어의 길이 2 배열에서 `a[2]`를 읽으면 모두 반드시 실행 중 범위 초과 예외가 난다는 ④를 선택했다. 실제 정답은 ②로, Java는 `ArrayIndexOutOfBoundsException`이 발생하고 C는 정의되지 않은 동작이다. C 실행에서 숫자가 출력되거나 프로그램이 종료될 수 있어도 어떤 결과도 보장되지 않는다는 점을 해설했다. [[06-오답-복습]]
- **정의되지 않은 동작의 관찰 결과 해석 추가 확인은 정답**이었다. C의 범위 밖 읽기에서 우연히 숫자가 출력돼도 올바른 접근이 되지 않고 다음 실행 결과도 보장되지 않는다는 ③을 선택했다. 이후 널 문자 `'\0'`로 끝나는 C 문자열과 `sizeof`·`strlen`의 차이를 소개했다. [[03-프로그래밍-언어#C 문자열의 널 종료와 길이]]
- **C 문자열 길이 첫 문제는 오답**이었다. `char s[]="cat";`의 `sizeof(s)`·`strlen(s)`를 `3 3`으로 선택했고 `sizeof`가 기억나지 않는다고 밝혔다. 실제는 널 문자까지 포함한 배열 네 칸의 크기 **4바이트**와 널 문자 전의 길이 **3**이므로 `4 3`이다. `sizeof`를 바이트 단위 저장 공간 크기를 구하는 연산자로 다시 설명하고 배열 네 칸을 표로 나타냈다. [[06-오답-복습]]
- **`sizeof`·`strlen` 후속 확인 1문제는 정답**이었다. `char s[]="hi";`에서 전체 배열 크기 3바이트와 널 문자 앞의 길이 2를 구분해 `3 2`를 선택했다. 배열 크기를 직접 정한 `char t[8]="go";`에서는 저장 공간 8바이트와 문자열 길이 2로 달라진다는 예를 설명했다. [[03-프로그래밍-언어#C 문자열의 널 종료와 길이]]
- **명시적 크기 문자열 배열 적용도 정답**이었다. `char s[6]="hi";`의 `sizeof(s)`·`strlen(s)`가 `6 2`라는 ③을 선택했다. 이어 `strcmp(a,b)`가 문자열 내용이 같으면 0을 반환하며, 별개의 두 배열에 대한 `a==b`는 내용 비교가 아니라 주소 비교라는 개념을 소개했다. [[03-프로그래밍-언어#C 문자열 내용 비교]]
- **C 문자열 내용 비교 첫 문제는 오답**이었다. 별개 배열에 같은 문자열 `"cat"`을 저장한 뒤 참인 식으로 `strcmp(a,b)==1`인 ④를 선택했다. 실제 정답은 내용이 같을 때의 `strcmp(a,b)==0`인 ②다. `a==b`가 거짓인 이유는 두 배열이 별개라는 점으로 직접 짚었다. `strcmp`는 같으면 정확히 0, 다르면 부호만 보장되므로 `==1`로 같음을 검사하지 않는다고 해설했다. [[06-오답-복습]]
- **`strcmp` 결과 부호 후속 문제는 정답**이었다. `"cat"`과 `"car"`의 첫 다른 문자 `t`·`r`을 비교하면 앞 문자열이 뒤에 오므로 결과가 양수라는 ②를 선택했다. 양수의 정확한 크기는 보장되지 않는다고 확인했다. 이어 Java 상속·오버라이딩을 소개하고 첫 코드 문제를 제시했다. [[03-프로그래밍-언어#C 문자열 내용 비교]] · [[03-프로그래밍-언어#Java 상속과 메서드 오버라이딩]]
- **Java 상속·오버라이딩 첫 코드 문제는 정답**이었다. `Animal a = new Dog();`에서 `a.sound()`가 `"dog"`를 출력하는 ②를 선택했다. 부모 타입 변수와 실제 Dog 객체를 구분하고, 재정의된 인스턴스 메서드가 호출된다는 점을 해설했다. [[03-프로그래밍-언어#Java 상속과 메서드 오버라이딩]]
- **상속받은 메서드 내부의 재정의 호출도 정답**이었다. `Animal.describe()` 안에서 `sound()`를 호출해도 실제 Dog 객체의 메서드가 실행되어 `"sound=dog"`가 출력되는 ④를 선택했다. `describe()`에서 붙인 `"sound="`와 동적 메서드 호출을 나눠 해설했다. [[03-프로그래밍-언어#Java 상속과 메서드 오버라이딩]]
- **`super` 호출 문제도 정답**이었다. Dog의 `sound()` 안에서 `super.sound() + "-dog"`를 반환할 때 `Animal a = new Dog(); a.sound()`의 결과 `"animal-dog"`인 ③을 선택했다. Dog 메서드가 실행된 후 부모 구현에서 `"animal"`을 가져오는 순서를 해설했다. 다음에는 같은 이름의 필드와 오버라이딩된 메서드의 선택 기준 차이를 확인한다. [[03-프로그래밍-언어#Java 상속과 메서드 오버라이딩]] · [[03-프로그래밍-언어#Java 필드 숨김과 메서드 오버라이딩]]
- **Java 필드 숨김·메서드 비교 첫 문제는 오답**이었다. `Animal a = new Dog();`에서 `a.name + " " + a.sound()`의 결과를 `dog dog`인 ④로 선택했다. 실제 정답은 **② `animal dog`**다. 필드 `a.name`은 선언 타입 Animal, 오버라이딩된 메서드 `a.sound()`는 실제 Dog 객체를 기준으로 선택한다고 분리해 해설했다. [[06-오답-복습]]
- **같은 객체를 두 타입의 변수로 참조하는 후속 문제도 오답**이었다. `Dog d = new Dog(); Animal a = d;`에서 `a.name + " " + d.name`을 `dog dog`인 ①로 선택했다. 실제 정답은 **③ `animal dog`**다. 같은 Dog 객체에 Animal의 `name`과 Dog의 `name` 필드가 따로 있고, 표현식의 변수 선언 타입에 따라 읽는 필드가 달라진다고 도식으로 설명했다. [[03-프로그래밍-언어#Java 필드 숨김과 메서드 오버라이딩]] · [[06-오답-복습]]
- **한 필드만 읽는 확인 문제는 정답**이었다. `Animal a = new Dog();`에서 `a.name`의 결과가 `"animal"`인 ①을 선택했다. 두 번의 혼합 문제 오답 뒤 필드 하나의 선택을 확인했으므로, 새 이름·숫자로 필드와 메서드를 함께 읽는 문제는 답변 대기 중이다. [[03-프로그래밍-언어#Java 필드 숨김과 메서드 오버라이딩]]

- `*p+1`과 `*(p+1)`은 각각 어떤 값을 계산하는가? 어느 문장에서 p나 원소가 바뀌는가?

- `char s[]="cat";`에서 배열에 저장되는 원소는 무엇이며 `sizeof(s)`와 `strlen(s)`는 왜 다른가?
- `char t[8]="go";`에서는 `sizeof(t)`와 `strlen(t)`가 각각 얼마인가?
- C에서 별개 배열에 같은 문자열을 저장했을 때 내용이 같은지 어떻게 검사하는가?
- `strcmp`의 결과가 0, 양수, 음수인 경우는 각각 무엇을 뜻하는가?
- Java에서 부모 타입 변수가 자식 객체를 가리킬 때, 오버라이딩된 인스턴스 메서드는 어느 클래스의 구현을 실행하는가?
- 상속받은 메서드 안에서 재정의된 메서드를 호출하면 어느 구현이 실행되는가? `super`를 쓰면 무엇이 달라지는가?
- 부모 타입 변수로 자식 객체를 참조할 때 같은 이름의 필드와 오버라이딩된 메서드는 각각 무엇을 기준으로 선택하는가?
