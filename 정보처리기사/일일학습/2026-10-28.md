## 오늘 다룬 내용

- 전날 제시한 Java 배열 기초 3문제 중 **1·2번 정답으로 2/3**이었다. `a[2]`가 30이라는 값 읽기와 2·4·6의 누적 합계 12는 맞혔다.
- 길이 3인 배열을 `i <= a.length`로 순회하는 3번에서 정상 종료 보기를 선택했다. 실제로는 5·10·15를 출력한 뒤 `a[3]`에서 실행 중 범위 초과 예외가 발생한다는 점을 표로 해설했다.
- 배열 길이와 마지막 유효 인덱스, `i < a.length`와 `i <= a.length`, 컴파일 오류와 실행 중 예외를 구분했다. 오류 이전 출력은 남고, 예외 처리가 없는 코드에서는 오류 이후 문장을 실행하지 않는다는 점을 설명했다.
- 배열 경계 추가 확인 **2문제 모두 정답**이었다. 마지막 원소는 `a[a.length - 1]`로 접근하며, `{3,6}`을 `i <= a.length`로 순회하면 3·6 출력 후 오류가 발생해 뒤의 99는 출력하지 않는다고 맞혔다.
- 배열 원소 변경 적용 **3문제 모두 정답**이었다. `a[1]=a[0]+5`의 결과 7, 원소별 2배 갱신 후 마지막 값 6, 앞 원소를 누적한 배열 `{1,3,6,10}`의 마지막 값 10을 맞혔다. 변경된 값이 다음 계산에 반영되는 과정을 표로 설명했다.
- **while·break·continue 적용 3문제 모두 정답**이었다. while의 1부터 3까지 합계는 6, i가 3일 때 break하면 1·2 출력 후 반복문 밖의 9 출력, continue이면 3만 제외한 합계 12라는 결과를 맞혔다.
- **do-while·중첩 반복문 적용은 2·3번 정답으로 2/3**이었다. 바깥 2회·안쪽 3회의 실행 횟수 6과, 안쪽 break가 있을 때 바깥 3회마다 2번씩 증가해 합계 6이라는 결과는 맞혔다.
- `int i=5; do{i++;}while(i<3);`의 결과를 5로 답했다. 본문에서 6으로 증가한 뒤 조건을 검사하므로 출력은 6이라는 과정을 표로 해설하고, 같은 조건의 while은 0회 실행되어 5라는 점과 비교했다.
- while·do-while 추가 확인 **2문제는 모두 오답(0/2)**이었다. 초기값 4·조건 `n<2`의 비교에서 A(while)=5·B(do-while)=5를 선택했으나 실제로는 A=4·B=5다. `n=1`에서 2씩 증가하고 `n<5`를 검사하는 do-while에서는 7을 선택했으나 실제 결과는 5다.
- while은 첫 조건이 거짓이면 본문을 실행하지 않는다는 점과, do-while도 매번 본문 뒤 조건을 검사해 거짓이면 즉시 반복을 종료한다는 점을 다시 설명했다. 1→3에서 참, 3→5에서 거짓이 되는 실행을 표와 단계별 시각화로 추적했다. 선택 결과만 기록하며 혼동 원인은 단정하지 않는다.
- 종료 조건에 집중한 추가 확인 **1문제는 정답**이었다. `n=2`에서 본문으로 2를 더한 뒤 `n<4`를 검사하는 코드의 출력 4를 선택했다. `2→4`, `4<4`는 거짓이므로 종료한다는 과정을 해설했다.
- 초기 조건이 거짓인 while과 do-while의 비교 확인 **1문제도 정답**이었다. 초기값 6·조건 `n<4`·본문 `n=n-2`에서 A(while)는 6, B(do-while)는 4를 선택했다. 후속 두 확인에서 정답을 선택했으므로 다음 개념으로 진행하고, 검사 시점은 간격을 두고 복습한다.
- **Java 메서드 코드 문제 3개 모두 정답**이었다. twice(4)의 반환값 8, plus(x)에서 int 매개변수만 바꿔 x=5·y=8이 되는 합계 13, f(3)=5·f(6)=5의 합계 10을 맞혔다. 조건 안에서 return을 만나면 현재 호출이 끝나는 점을 확인했다.
- **배열 인수 전달 적용 문제는 1·3번 정답으로 2/3**이었다. 같은 배열의 첫 원소를 9로 바꾸는 경우와, int 변수 x=3을 유지하면서 배열 원소를 10으로 바꿔 합계 13이 되는 경우는 맞혔다.
- 메서드에서 `a = new int[]{9,9};`를 실행한 뒤 호출한 쪽 `x[0]`을 읽는 2번에 9를 선택했다. 실제로는 x가 기존 `{1,2}`를 계속 가리켜 결과는 1이다. a에 새 참조값을 대입하는 것은 x의 참조값을 바꾸지 않는다는 점을 연결 그림으로 해설했다.
- 배열 원소 변경·참조값 재대입 추가 확인 **1문제는 정답**이었다. 사용자가 기존 배열의 첫 원소를 7로 바꾼 뒤 a에 새 배열을 대입해도 x는 `{7,2}`로 남는다고 직접 설명했다. 마지막 합계는 9이며, 이후 `a[1]=8`은 새 배열만 바꾼다는 점을 표로 해설했다.
- 표현을 다듬어 `a[0]=7`은 원소 대입, `a=new int[]{9,9}`는 새 배열 생성 후 참조값 재대입으로 구분했다. **C 주소·포인터 첫 확인은 1번만 정답으로 1/3**이었다. `p=&x` 뒤 `*p=7`로 x를 바꾸는 경우는 맞혔다.
- `int x=3; int y=x; y=8;` 뒤 x를 8로 답했으나 실제 값은 3이다. `p=&x` 후 `p=&y; *p=9;`를 실행할 때는 x·y를 `9 5`로 답했으나 실제 결과는 `2 9`다. 값 복사 후 별개 변수에 대입하는 경우와 포인터의 현재 대상 변경을 표로 추적해 설명했다.
- C 값 복사·포인터 대상 변경 추가 확인은 **1번만 정답으로 1/2**이었다. `a=4; b=a; b=b+2;`의 결과 `4 6`은 맞혔다. `a=4`, `b=6`에서 p를 b로 바꾼 뒤 `*p=*p+1`을 실행하는 문제는 `5 6`으로 답했으나 실제 결과는 `4 7`이다.
- `p=&b` 뒤 양쪽 `*p`가 모두 b에 접근하므로 해당 문장을 `b=b+1`로 읽는 과정을 다시 설명했다. 현재 대상만 묻는 미세 확인 **1문제는 정답**이었다. `p=&a` 다음 `p=&b`를 실행한 뒤 대상은 b라고 선택했다. 선택 결과만으로 혼동 원인은 단정하지 않는다.
- 주소 재대입 후 역참조 실행 결과 확인 **1문제도 정답**이었다. a=3·b=8에서 p를 b에서 a로 바꾸고 `*p=*p+2`를 실행하는 결과 `5 8`을 선택했다. 그 시점의 대입은 `a=a+2`로 읽는다고 해설했다. 선택 정답을 근거로 다음 개념에 진행하고, 포인터 대상 추적은 간격을 두고 복습한다.
- **C 함수의 값·포인터 인수와 반환값 확인 3문제 모두 정답**이었다. 값 인수의 복사본만 수정하면 x=3 유지, 포인터로 수정하면 x=5, 반환값을 x에 다시 대입해도 x=5라는 결과를 맞혔다.
- **C 포인터 인수 응용은 2·3번 정답으로 2/3**이었다. 포인터로 호출자 변수의 값을 교환하는 결과 `7 2`와, `p=q` 뒤 y만 9로 바뀌는 결과 `2 9`는 맞혔다.
- 일반 int 매개변수 a·b를 교환한 뒤 호출자 x·y를 출력하는 1번에서 `7 2`를 선택했다. 실제 출력은 `2 7`이다. 함수 안의 복사본 a·b는 교환되지만 main의 x·y는 그대로라는 점을 표로 설명했다.
- 함수 안·밖 출력 구분 추가 확인 **1문제는 정답**이었다. 함수 안에서 n을 8로 바꿔 출력한 뒤, main에서 그대로인 x=3을 출력하는 결과 `8 3`을 선택했다. 복사본과 호출한 쪽 변수는 간격을 두고 복습한다.
- **C 배열과 포인터 적용 3문제 모두 정답**이었다. `*(p+1)`로 두 번째 원소 20을 읽고, p를 두 번째 원소로 옮겨 9를 대입한 뒤 배열이 `{2,9,6}`이 되는 결과, `*p`와 `*(p+2)`로 첫째·셋째 원소 `3 9`를 읽는 결과를 맞혔다.
- 이어서 `*p+1`은 현재 원소의 값에 1을 더하고, `*(p+1)`은 다음 원소의 값을 읽는다는 차이를 설명했다. 계산만 하는 표현식은 p나 배열을 바꾸지 않는다. 구분 적용은 **1·2번 정답, 3번 오답으로 2/3**이었다. `*p+1`과 `*(p+1)`의 결과 `4 5`, `p=a+1` 뒤의 `20 30`은 맞혔다.
- `a[]={2,4,6}; p=a; *p=*p+1; p=p+1;` 뒤 `a[0]`과 `*p`에 `2 5`를 선택했다. 실제 결과는 `3 4`다. 원소 값 대입 후 포인터 위치 이동을 표로 분리해 설명했다. 두 동작을 나눠 묻는 추가 확인 2문제는 답변 대기 중이다.
