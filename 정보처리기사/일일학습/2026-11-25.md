# 2026-11-25

## 학습과 확인 결과

- [[../05-운영체제와-네트워크#/25의 경계|/25 동일 서브넷 판단]]: `192.168.30.160/25`와 `192.168.30.220/25`를 같은 서브넷으로 판단하고 둘 다 128~255에 속한다는 근거를 설명했다. 이전의 서로 다른 구간 비교 오답과 구분하며, 이번 같은 구간 적용의 정답을 확인했다. 숙달은 단정하지 않는다.
- [[../05-운영체제와-네트워크#네트워크·브로드캐스트·호스트 할당 범위|주소 역할과 호스트 할당 범위]]: 두 번째 `/25` 구간에서 첫 주소 `.128`은 네트워크 주소, 마지막 `.255`는 브로드캐스트 주소이며 중간 `.129~.254`가 일반 호스트 할당 범위임을 설명했다. 총 128개 중 두 주소를 제외해 126개다.
- `/25` 범위 적용: `192.168.30.70/25`의 네트워크 주소를 `.0`, 호스트 할당 범위를 `.1~.126`으로 정확히 답했다. 브로드캐스트 `.127`은 해설로 설명했다. 이번 범위 적용은 확인했으며 숙달을 단정하지 않는다.
- [[../05-운영체제와-네트워크#/26의 구간|/26 구간]]: 호스트 6비트·전체 주소 64개, 마스크 `255.255.255.192`, 마지막 묶음의 0~63·64~127·128~191·192~255 구간을 설명했다. `/25`의 각 구간을 절반으로 나누는 원리로 연결했다.
- `/26` 구간 적용: `192.168.30.100/26`이 속한 전체 주소 구간을 `192.168.30.64~127`로 정확히 답했다. 이번 구간 적용은 확인했으며 숙달을 단정하지 않는다.
- `/26` 주소 역할 적용: 같은 구간의 네트워크 주소 `.64`, 브로드캐스트 주소 `.127`, 호스트 할당 범위 `.65~.126`을 모두 정확히 답했다. 이번 적용을 확인했으며 숙달을 단정하지 않는다.
- [[../05-운영체제와-네트워크#호스트 수와 접두사 선택|호스트 수]]: `/26`의 호스트 수는 `126-65+1=62`, 또는 전체 64개에서 두 주소를 제외해 62개임을 설명했다. `/25`의 126개와 비교해 요구 호스트 수의 수용 여부로 연결했다.
- 수용량 비교 적용: 호스트 주소 70개가 필요한 문제에서 `/25`를 선택하고 `/26`은 62개로 부족하며 `/25`는 126개까지 할당할 수 있다고 정확히 설명했다. 이번 요구 수용량 판단을 확인했으며 숙달을 단정하지 않는다.
- 최소 주소 수 선택 방법: 필요한 호스트 수에 두 주소를 더하고, 그 이상인 최소 `2^h`에서 호스트 비트 `h`를 구한 뒤 `32-h`로 접두사를 구하는 방법을 설명했다. 기존 70개 사례의 `72→128=2^7→/25`로 연결했다.
- 호스트 30개 적용: 호스트 5비트는 정확히 답했으나 접두사는 23으로 답했다. IPv4 전체 32비트에서 호스트 5비트를 빼 네트워크 27비트·접두사 `/27`임을 설명했다. `30+2=32개`의 주소 개수와 IPv4 32비트의 주소 길이는 단위가 다름을 짚었다. 오답 원인은 추정하지 않는다.
- 접두사 변환 후속: 호스트 부분이 6비트이면 접두사는 `/26`이라고 정확히 답했다. 이번 변환은 확인했으며 전체 산출 과정의 숙달을 단정하지 않는다.
- 다음 시작점: 일반 호스트 주소 50개를 수용하면서 전체 주소 수가 가장 적은 서브넷의 전체 주소 수·호스트 비트 수·접두사를 답한다. 새로운 요구 수량에 대한 단계 결합 적용은 아직 미확인이다.
