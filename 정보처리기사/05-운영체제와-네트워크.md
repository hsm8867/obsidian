# 운영체제와 네트워크

[[00-학습-허브]] · [[06-오답-복습]]

## 프로세스와 스레드

- **프로세스**: 실행 중인 프로그램의 독립적인 실행 환경.
- **스레드**: 프로세스 안의 실행 흐름. 한 프로세스에 여러 스레드가 있을 수 있다.
- 같은 프로세스의 스레드는 **주소 공간의 일부(예: 힙)를 공유**하지만, 각 스레드는 자기 실행 상태(예: 스택·레지스터·프로그램 카운터)를 갖는다.

```text
프로세스 하나
├─ 공유: 코드, 힙 등의 주소 공간
├─ 스레드 A: 자체 스택·실행 위치
└─ 스레드 B: 자체 스택·실행 위치
```

### Python의 GIL과 헷갈리지 않기

일반적인 **CPython** 빌드의 GIL은 여러 스레드를 **만들지 못하게 하는 제한이 아니다.** 한 시점에 Python 코드를 실행하는 스레드를 제한한다. 그래서 I/O 대기 중 다른 스레드가 진행할 수 있지만, 순수 Python 계산을 여러 코어에서 동시에 실행하는 데는 제약이 있다. 일부 확장 모듈은 GIL을 해제할 수 있고, GIL을 끄는 별도 free-threaded 빌드도 있다.

시험 기본 개념: **한 프로세스에 여러 스레드가 있고 메모리를 공유할 수 있다.**

참고: [Python `threading` 문서](https://docs.python.org/3/library/threading.html), [Python free-threading 문서](https://docs.python.org/3/howto/free-threading-python.html)

## 라운드 로빈 CPU 스케줄링

**라운드 로빈(Round Robin)**은 대기 중인 작업에 정해진 시간 할당량(time quantum)만큼 차례로 CPU를 준다. 시간이 끝나도 작업이 남으면 대기 줄 뒤로 보낸다.

P1에 5ms, P2에 3ms가 필요하고, 시간 할당량이 2ms이며 P1이 먼저 시작하면:

```text
시간       0–2   2–4   4–6   6–7   7–8
CPU 사용    P1    P2    P1    P2    P1
```

시간 할당량이 너무 짧으면 작업을 바꾸는 **문맥 교환**이 잦아져 비용이 커진다. 확인: P1=3ms, P2=2ms, 할당량=2ms라면 4~5ms에는 **P1**이 실행된다.

## 가상 메모리와 페이징

**가상 메모리**는 프로세스가 사용하는 논리 주소 공간을 물리 메모리와 분리한다. 따라서 프로그램은 자신의 주소 공간을 기준으로 접근하고, 운영체제와 하드웨어가 이를 실제 물리 메모리 위치로 변환한다. 필요한 부분만 물리 메모리에 올려 사용할 수 있다.

**페이징**에서는 가상 주소 공간을 고정 크기의 **페이지**, 물리 메모리를 같은 크기의 **프레임**으로 나눈다. 페이지 테이블은 페이지 번호가 어느 프레임에 있는지 알려준다. 프로그램의 페이지가 물리 메모리에서 연속으로 놓일 필요는 없다. 가변 크기의 구역으로 나누는 **세그먼테이션**과 구별한다.

```text
가상 주소 = [페이지 번호 | 페이지 내부 변위]
                       ↓ 페이지 테이블에서 프레임 찾기
물리 주소 = [프레임 번호 | 같은 내부 변위]
```

페이지 크기가 **4 KiB**이고 주소가 바이트 단위라면, 한 페이지에는 `4 × 1024 = 4096 = 2^12`개의 바이트 위치가 있다. 따라서 **페이지 내부 변위는 12비트**다. 페이지 번호의 비트 수는 전체 가상 주소 길이를 알아야 계산할 수 있다.

### 페이지 부재와 스래싱

- **페이지 부재(page fault):** 유효한 가상 주소의 페이지가 현재 물리 메모리에 없을 때 발생한다. 운영체제가 필요한 페이지를 가져와 페이지 테이블을 갱신한 뒤 해당 명령을 다시 실행한다. 유효하지 않은 주소나 접근 권한 위반은 프로그램 오류로 처리될 수 있으므로 구분한다.
- **스래싱(thrashing):** 사용할 프레임이 부족해 페이지를 계속 교체하느라 실제 작업보다 페이지 입출력에 많은 시간을 쓰는 상태다. CPU 이용률이 떨어질 수 있다.
- **TLB:** 최근 주소 변환 결과를 보관하는 캐시다. TLB 적중은 주소 변환을 빠르게 하며, 스래싱의 정의가 아니다.

## 교착상태: 순환 대기

A가 B의 자원을 기다리고 B가 다시 A의 자원을 기다리는 **기다림의 고리**가 순환 대기다. 교착상태를 일으키는 필요조건 중 하나다.

## DNS와 TCP 및 UDP

| 개념 | 핵심 |
|---|---|
| **DNS** | 도메인 이름에 대응하는 IP 주소를 찾는 데 사용한다. |
| **TCP** | 연결 지향적이며 신뢰성 있는 전송을 제공한다. |
| **UDP** | 연결 설정 없이 데이터를 보내며, 도착·순서를 자체적으로 보장하지 않는다. |

TCP 연결을 시작하는 **3단계 핸드셰이크**:

```text
클라이언트 → 서버: SYN
서버 → 클라이언트: SYN-ACK
클라이언트 → 서버: ACK
```

암기: **SYN → SYN-ACK → ACK**. DNS의 주된 역할은 패킷 암호화가 아니다.
